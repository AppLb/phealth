# pHealth — phealth.kz

Сайт собирается генератором [Eleventy](https://www.11ty.dev/) из файлов в `src/`.

## Как сайт попадает на hoster.kz

1. Изменения вливаются в ветку `main` (merge pull request).
2. GitHub Actions собирает сайт (около минуты, вкладка **Actions**) и кладёт готовые файлы в ветку `site`.
3. В Plesk нажать «Развернуть» — Plesk забирает ветку `site`.

Ветку `site` руками не трогать: её перезаписывает сборка.

## Где что лежит

| Общие стили и скрипты | `src/assets/` |

## Новая заметка журнала

Создать файл в `src/notes/`, например `src/notes/zheleso-i-chay.md`:

```markdown
---
title: "Почему железо не пьют с чаем"
date: 2026-11-20
topic: Добавки
---
Первый абзац.

Второй абзац.
```

`topic` — одна из тем в `src/_data/topics.json`. Заметка сама появится на главной, новые сверху.

## Новая статья

Создать папку с файлом `index.md`, например `src/omega-3/index.md`. Шапку (front matter) взять из `src/vitamin-d/index.md`.

Самая новая статья сама становится большой карточкой журнала на главной, остальные уходят в список под ней. Для карточки в шапке нужны `cover` (буквы на обложке) и `teaser` (одна-две фразы). Цвет темы берётся из `src/_data/topics.json`.

Обложка статьи — файл `cover.svg` в её папке: узор из деталей логотипа на синем фоне, размер 360×120 (пример в `src/vitamin-d/cover.svg`). Если файла нет, подставится запасной узор из `src/_includes/covers/default.svg`. Все статьи и заметки собраны на странице `/journal/` (`src/journal/index.njk`), новая статья появляется там сама.

Автор разборов — `author: Редакция pHealth`, рядом с подписью встанет значок редакции: белый ромб на синей плашке (`src/_includes/partials/editor-badge.njk`). У личного текста в `author` пишется имя, рядом будет квадратик с первой буквой.

Время чтения считается при сборке само: слова лида и текста делятся на 180 слов в минуту. Оно показывается в шапке статьи и на карточках журнала.

В тексте:

- `## Заголовок раздела`
- `{% ctx %}Пояснение под заголовком{% endctx %}`
- `{% claim 3 %}Утверждение с меткой.{% ref 2 %}{% endclaim %}` — метка 4 «Сильные», 3 «Умеренные», 2 «Ограниченные», 1 «Не подтверждено»
- `{% ref 2 %}` — сноска на второй источник из списка `sources`
- источник в `sources` может быть строкой или парой `text` + `url` — тогда он станет ссылкой (пример в `src/co2-i-mozg/index.md`)
- `{% term "ppm" %}ppm{% endterm %}` — понятие из словаря: пунктирная ссылка, по нажатию карточка с объяснением и ссылкой на понятие в словаре. Слаг — имя файла в `src/slovar/`; если такого файла нет, сборка остановится с ошибкой
- `{% note "Коротко." %}Текст врезки{% endnote %}`, спорное место: `{% note "Спорное место: …", "dispute" %}…{% endnote %}`

## Словарь

Понятия лежат в `src/slovar/`, одно понятие — один файл, например `src/slovar/ppm.md`:

```markdown
---
title: "ppm"
short: "Частей на миллион. 1000 ppm углекислого газа — это 0,1% воздуха."
group: "Воздух"
order: 1
related: [co-i-co2, ndir]
---
Пара абзацев объяснения.
```

Все понятия собраны на одной странице `/slovar/`, каждое — раскрывающийся пункт. `short` видно сразу, текст понятия — после раскрытия; он же коротко показывается в карточке в статье. Ссылка `/slovar/#ppm` раскрывает нужное понятие. `group` — одна из групп, перечисленных в `src/slovar/index.njk`. `related` — слаги соседних понятий. Список «Встречается» собирается сам: это страницы, где понятие отмечено `{% term %}`.

## Собрать у себя

```
npm install
npm start
```

Сайт откроется на http://localhost:8080 и будет обновляться при сохранении файлов.
